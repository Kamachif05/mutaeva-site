## Основная схема

Публичная страница остаётся на GitHub Pages. `https://admin.mutaeva.ru` обслуживает вход, редактор и `/api/prices` на выделенном VPS. Страница читает общедоступные цены без cookie; операции записи доступны только в админке после входа. Дополнительный платный сервис не требуется.

В `config.js` перед публикацией указать:

```js
window.MUTAEVA_CONFIG = Object.freeze({ apiBase: 'https://admin.mutaeva.ru' });
```

Открытие `/admin/` на GitHub Pages перенаправляет пользователя на адрес сервиса. При локальном просмотре `apiBase` остаётся пустым.

## Порядок повторного размещения

1. Создать DNS A-запись `admin` в зоне `mutaeva.ru`, указывающую на предоставленный VPS. Проверить запись через авторитетные DNS-серверы. Не менять A-записи главного домена. Не создавать AAAA без настроенного IPv6.
2. Установить отдельный файл `deploy/nginx-admin.conf` в Nginx, проверить конфигурацию и выполнить плавную перезагрузку. Чужие файлы сайтов не заменять.
3. Получить сертификат для `admin.mutaeva.ru`, включить перенаправление HTTP на HTTPS. Запись через HTTP запрещена применением Secure cookie.
4. Проверить вход, сохранение, повторное чтение и выход через реальный HTTPS-домен.
5. Указать `apiBase`, выполнить сборку и проверки, отправить ветку на GitHub, открыть изменение для приёмки. Публиковать в основную ветку только после команды владельца.
6. Проверить реальный `mutaeva.ru`: оба города, поиск, цены после редактирования, мобильную версию и действующие ссылки записи.

## Учётная запись и обслуживание

Сервер получает отпечаток пароля через `LoadCredential`; исходный закрытый файл расположен в `/srv/mutaeva-site/secrets/admin.json`. Локальная выдача нового доступа находится в закрытой папке `secrets`, исключённой из Git. Пароль SSH туда не записывался.

После настройки сервера не запускать несколько процессов с одним хранилищем: очередь и контроль версии действуют в рамках одного процесса. Unit запускает ровно один процесс. Архивировать `/var/lib/mutaeva-site` отдельно от исходников; в Git его не добавлять. Резервные версии накапливаются, срок хранения владелец задаёт отдельно. Для сброса пароля остановить только свой сервис, заменить отпечаток с сохранением владельца и доступа, запустить и проверить вход.

## Приёмка владельцем

1. Сравнить главную страницу и мобильный вид с сохранёнными снимками.
2. Войти в админку, найти услугу, поменять цену только Москвы и сохранить.
3. На сайте проверить новую цену Москвы и прежнюю цену Махачкалы; вернуть исходную сумму.
4. Убедиться, что после выхода сохранить цену нельзя, отрицательная сумма блокируется, а две вкладки показывают конфликт вместо потери изменений.
5. Принять оформление и работу через реальный домен после публикации. Локальные проверки и подготовленный VPS не заменяют эту приёмку.
